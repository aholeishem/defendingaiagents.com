E3 · שיעור 03

קריאה אחת לכלי, שלושה פורמטים על הקו

כל הספקים מסכימים על הרעיון של קריאה לכלי (tool call), ולא מסכימים על איך היא נראית על הקו (wire format). סוכן שעובר ממודל מקומי למודל מתארח, או מ־API מתארח אחד לאחר, נשבר בדיוק בנקודות המחלוקת האלה, בדרך כלל בקריאה המקבילה הראשונה או בכלי הראשון בלי ארגומנטים. התרופה היא הרגילה: פורמט פנימי אחד, ומתאם (adapter) בכל קצה.

אותה קריאה, בשלוש דרכים

"Read notes/a.txt", כתשובה של המודל וכתוצאה שהלולאה שלכם שולחת בחזרה:

Chat Completions (ה־API הישן יותר של OpenAI; מוגש על ידי Ollama, llama.cpp, vLLM ו־LM Studio):

{"role": "assistant", "content": "",
 "tool_calls": [{"id": "call_1", "type": "function",
                 "function": {"name": "read_file", "arguments": "{\"path\": \"notes/a.txt\"}"}}]}
{"role": "tool", "tool_call_id": "call_1", "content": "alpha"}

Responses (ה־API החדש יותר של OpenAI): התשובה היא רשימה של פריטי פלט, וסכמת הכלי שטוחה.

{"type": "function_call", "call_id": "call_1", "name": "read_file", "arguments": "{\"path\": \"notes/a.txt\"}"}
{"type": "function_call_output", "call_id": "call_1", "output": "alpha"}

Anthropic Messages: תשובה היא רשימה של בלוקי תוכן, ואין תפקיד (role) של tool.

{"role": "assistant", "content": [{"type": "tool_use", "id": "toolu_1", "name": "read_file",
                                   "input": {"path": "notes/a.txt"}}]}
{"role": "user", "content": [{"type": "tool_result", "tool_use_id": "toolu_1", "content": "alpha"}]}

שלושה מאלה הם התנהגות, לא איות.

  • מחרוזת או אובייקט. רק מחרוזת יכולה להיות פגומה (שיעור 2). מתאם מ־Anthropic ל־Chat Completions חייב לבצע סריאליזציה ל־input, ומתאם בכיוון ההפוך חייב לפענח את arguments. מחרוזת ריקה פירושה {}, והצד של Anthropic צריך אובייקט.
  • הודעת user אחת לכל התוצאות. התיעוד של Anthropic אומר ששליחת כל תוצאה בהודעת user נפרדת «מלמדת» את המודל להפסיק לבצע קריאות מקבילות. ההיסטוריה היא פרומפט few-shot, והפורמט שלה הוא חלק ממה שהמודל לומד ממנה.
  • פרומפט המערכת זז. השאירו הודעת system ברשימת ה־messages של Anthropic, והבקשה נכשלת. הורידו אותה בשקט, ואיבדתם את ההוראות.

מתאם בקצה

loop/formats.py שומר על Chat Completions בתוך הלולאה וממיר בקצוות:

body = to_anthropic_request(messages, tools.schemas, model="...", max_tokens=1024)   # history out
message, usage = from_anthropic_response(resp)                                       # reply in

to_anthropic_request מעלה את הודעות המערכת לתוך system, הופך כל הודעת assistant לבלוק טקסט ואחריו בלוקי tool_use עם ארגומנטים מפוענחים, ואוסף הודעות tool רצופות להודעת user אחת של בלוקי tool_result. from_anthropic_response עושה את ההפך, ומשנה את שמות שדות השימוש כך שהתקציב (שיעור 6) יחייב באותה דרך, לא משנה מי הגיש את הקריאה. המתאם ל־Responses מצורף, להשוואה.

הבדיקה מריצה את המתאמים האלה על צורות מוקלטות, לא על API חיים: הקורס לא דורש חשבון. אם יש לכם חשבון, שלחו פעם אחת את הפלט של to_anthropic_request ל־endpoint האמיתי. המתאם שלכם נכון כשה־tool_use של התשובה חוזר דרך from_anthropic_response והלולאה שלכם מריצה אותו.

פורמטים זזים

פורמטים על הקו אינם יציבים. OpenAI הוסיפה את Responses לצד Chat Completions. באוקטובר 2026 המדריך של Google ל־function calling ב־Gemini מתאר API חדש יותר בשם "Interactions", בעוד שדפים ישנים יותר עדיין מתארים חלקי functionCall. קורס שהיה מלמד פורמט אחד בתור הפורמט היה מתיישן תוך שנה. המיומנות שנשארת היא המתאם, עם בדיקה של צורות מוקלטות לכל פורמט שאתם תומכים בו, כדי שתשימו לב כשספק משנה אחד מהם.

בדקו את עצמכם

  1. בתור assistant יש שתי קריאות לכלים. כמה הודעות נושאות את התוצאות שלהן ב־Chat Completions, וכמה ב־Anthropic Messages?
  2. קריאה לכלי ב־Chat Completions מגיעה עם "arguments": "". מה המתאם ל־Anthropic חייב לשים ב־input, ולמה המחרוזת הריקה אינה אובייקט JSON?
  3. התקציב שלכם סופר prompt_tokens. מה משתבש אם המתאם ל־Anthropic מעביר את שדות השימוש בלי לשנות את שמותיהם?
תשובות
  1. שתיים ב־Chat Completions (הודעת tool אחת לכל קריאה), ואחת ב־Anthropic Messages: הודעת user יחידה שמחזיקה שני בלוקי tool_result.
  2. {}. המחרוזת הריקה אינה JSON תקין מאף טיפוס: json.loads("") זורק שגיאה. שרתים שולחים אותה במשמעות «אין ארגומנטים», ולכן המתאם חייב למפות אותה לאובייקט הריק, ש־input של Anthropic דורש.
  3. התקציב קורא את prompt_tokens ואת completion_tokens, לא מוצא אף אחד מהם, סופר אפס לכל קריאה, ומגבלות הטוקנים והעלות אף פעם לא נכנסות לפעולה. הריצה בלי גבול, ובלי שום שגיאה. זו הסיבה שהמתאם משנה את השמות של input_tokens ו־output_tokens, ושהבנייה בודקת תקציב טוקנים על שימוש מוקלט.
