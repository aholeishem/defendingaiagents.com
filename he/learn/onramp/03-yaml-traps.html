מסלול הכנה · שיעור 03

YAML הוא JSON עם הזחה וארבע מלכודות

צוות רושם בקובץ קונפיגורציה את המדינות המותרות: - GB, - DE, - NO. השירות עולה, ומשתמשים מנורווגיה נחסמים. טוען ה־YAML קרא את NO כערך הבוליאני false. אותו קובץ, שנטען באותו קוד, הוא מדיניות אחרת מזו שהכותב שלו קרא.

מיומנות הקריאה

YAML הוא הרחבה של JSON (מאז גרסה 1.2) שנכתבת בהזחה במקום בסוגריים מסולסלים (YAML, 2021). תפגשו אותו בכל קובץ קונפיגורציה בקורס: המעבדה, מדיניות, CI. שלוש צורות מכסות כמעט הכול:

name: acme-gateway          # a mapping: key, colon, space, value
allow:                      # a list is dashes at one indentation
  - crm.acme.example
  - cal.acme.example
limits: {rate: 10, burst: 20}   # JSON-style on one line is legal

ההזחה היא המבנה, והיא ברווחים, אף פעם לא בטאבים. # פותח הערה. שני רווחי הזחה פחות הם קובץ אחר.

מלכודת 1: מילים חשופות הופכות לטיפוסים

הריצו את זה, כמו שהכלים של הקורס עושים, עם הטוען שמחזיר דאטה בלבד:

import yaml
print(yaml.safe_load("country: no\nversion: 1.10\nports: [80, 0o17, 010]\nmode: 0755\non: yes"))
# {'country': False, 'version': 1.1, 'ports': [80, '0o17', 8], 'mode': 493, True: True}

no הוא False, 1.10 הוא המספר העשרוני 1.1 (מספר גרסה שאיבד את האפס שלו), 010 הוא 8 בבסיס אוקטלי, 0755 הוא ביטי ההרשאות 493, והמפתח on הוא הבוליאני True. אלה הטיפוסים המשתמעים של YAML 1.1 (הטיפוס הבוליאני של YAML 1.1 מונה את y, yes, on ואת השלילות שלהם; Boolean Language-Independent Type for YAML version 1.1, 2005). גרסה 1.2 מקצצת את הרשימה, אבל PyYAML, שרוב הכלים ב־Python משתמשים בו, עדיין מפרש את המילים של 1.1 (אם כי לא את האותיות הבודדות), כפי שההרצה למעלה מראה. שימו במירכאות מחרוזות שחייבות להישאר מחרוזות: "NO", "1.10".

מלכודת 2: מפתחות כפולים, שוב

yaml.safe_load("a: 1\na: 2")      # {'a': 2}

המאוחר מנצח בשקט, ובלוק שהועתק והודבק יכול להסתיר את המפתח שמעליו. אותו פער כמו בשיעור 2, בקובץ שבן אדם עורך.

מלכודת 3: load יכול להריץ קוד

יש טוענים שבונים אובייקטים שרירותיים מתגיות כמו !!python/object/apply:os.system. התיעוד של PyYAML אומר ש־yaml.load חזק כמו pickle.load ולכן עלול לקרוא לכל פונקציית Python (PyYAML documentation); safe_load דוחה תגית כזו עם ConstructorError. השתמשו בטוען הבטוח לכל קובץ שלא אתם כתבתם, וגם לאלה שכן, כי ייתכן שמישהו אחר יכול לערוך אותם.

מלכודת 4: עוגנים ומפתחות מיזוג

&base נותן שם לבלוק, ו־*base או <<: *base משתמשים בו שוב. קובץ מדיניות שממזג בלוק בסיס לעשרים כללים נקרא קצר יותר ונבדק לא נכון: הקורא רואה כלל, לא את השדות שהוא יורש. פרשו את הקובץ לפני סקירה (טענו אותו והדפיסו את התוצאה).

מומחה: למה בקרה קוראת דאטה, לא טקסט

קונפיגורציה של שער בקרה (gateway) שנטענת מחדש כשהיא משתנה היא control plane. טעינה שלה עם סכמה קפדנית וטיפוסית (השדה country הוא מחרוזת, וכל דבר אחר נכשל בטעינה) הופכת את מלכודת 1 לשגיאה בעלייה, ולא לשינוי מדיניות שקט. תכשילו את הטעינה, לא את הבקשה.

בדקו את עצמכם

  1. אילו מאלה נטענים כמחרוזת: id: 0x1F, id: "0x1F", id: 1_000, id: ~? הריצו.
  2. סוקר קורא כלל שאומר allow: [crm]. אילו שתי תכונות של YAML יכולות להפוך את הכלל בפועל לרחב יותר ממה שהוא קרא?
  3. למה «אנחנו טוענים רק קבצים מה־repo שלנו» הוא לא תשובה למלכודת 3? ואילו מארבע המלכודות נשארות פתוחות אחרי מעבר ל־safe_load?
תשובות
  1. רק id: "0x1F". safe_load של PyYAML קורא את 0x1F כמספר השלם 31, את 1_000 כ־1000 (YAML 1.1 מתיר קווים תחתונים במספרים שלמים) ואת ~ כ־None.
  2. מפתחות כפולים (מלכודת 2): allow: שני בהמשך אותו מיפוי מחליף בשקט את זה שהסוקר קרא. עוגנים ומפתחות מיזוג (מלכודת 4): <<: *base בכלל מכניס שדות שהסוקר לא רואה בעמוד. טעינת הקובץ והדפסת התוצאה מראות את הכלל שחל בפועל.
  3. כי «ה־repo שלנו» הוא קבוצה של כותבים, לא כותב אחד: כל תורם, חשבון פרוץ, שלב CI או כלי עם הרשאת כתיבה יכולים לשתול תגית !!python/object/apply, ו־load יריץ אותה. safe_load סוגר רק את מלכודת 3; טיפוסים משתמעים, מפתחות כפולים ומפתחות מיזוג מתנהגים בדיוק אותו דבר תחתיו, כפי שההרצות בשיעור עצמו מראות.
