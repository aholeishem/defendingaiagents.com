On-ramp: the web plumbing the course assumes

Statistical twin Reading a log line and a token as data: what a request, a name, a channel and a credential each prove, and what they do not.

The course reads agent traffic at the wire. A gateway sits on an HTTP connection, a token says who may call a server, a proxy is trusted or not, a name resolves to an address that may change between two lines of code. Every one of those is a few pages of plain specification. If you already read curl -i output and a decoded JWT without effort, skip this unit. If not, an afternoon here saves you from learning HTTP and OAuth and statistics at the same time. Lessons 1 to 9 are what the course assumes; the two Expert lessons are for readers who want to argue about these protocols with the people who design them.

It is theoretical in the course's sense: the value is a way of reading, not a component. The exercises are small commands you can run on a laptop with python3, curl and openssl, plus PyYAML for lesson 3 (pip install pyyaml) and the cryptography package for one problem. Nothing needs Docker or an account, and after those two installs nothing needs the network.

You will be able to

Each line ends with badges: its tier, the graduate outcome it builds (the map) and where it is assessed (a check group, a problem P, the build or a written answer). Hover over a badge for its meaning; select a tier or an outcome to filter the course map.

  • Split a URL and an HTTP message into scheme, userinfo, host, port, path, query, headers and body, and say which name a TLS handshake checks. <span class="label tier">Foundations</span>
  • Predict how two JSON parsers and a YAML safe loader read the same bytes, and name the disagreement a control must close. <span class="label tier">Foundations</span>
  • Decide where a bearer token may travel (header, query string, prompt, log line) and what to do instead where it may not. <span class="label tier">Foundations</span>
  • Design a name check that a rebinding resolver cannot defeat, by connecting to the address that was checked. <span class="label tier">Advanced</span>
  • Pick the client address out of a X-Forwarded-For chain, given the proxies you run. <span class="label tier">Advanced</span>
  • Test which names a wildcard certificate covers, and state what the handshake proved. <span class="label tier">Advanced</span>
  • Write a JWT verifier that checks algorithm, signature, issuer, audience and time in that order, with a lifetime policy. <span class="label tier">Advanced</span>
  • Demonstrate end to end the key confusion that reading the algorithm from the token allows. <span class="label tier">Expert</span>
  • Annotate an MCP authorization flow step by step with OAuth's roles, scope, aud and sub, and count the tokens per-call minting issues. <span class="label tier">Expert</span>
  • State when a check on a message is sound against the parser that acts on it, and choose among one parser, a smaller language and differential testing. <span class="label tier">Expert</span>
  • Audit an agent's OAuth client against RFC 9700's attacker model, and schedule a signing-key rotation from cache and token lifetimes. <span class="label tier">Expert</span>

Then: problems. There is no build and no make check; every lesson ends in something you run or read.

Where this stops

It teaches reading, not operating. Certificate authorities, OAuth login pages for people, DNSSEC, HTTP/2 framing and the many JWT algorithms are left to the specifications, and the lessons say where. Module 3 lesson 10 and Module 12 take the credentials further; they assume lessons 8 and 9.
