Module 00 · Paper exercise: where would you have stopped it?

Paper exercise: where would you have stopped it?

No code until Module 1. Twenty minutes with a pen.

Draw the loop from lesson 1 once per incident from lesson 2. On each drawing:

  1. Circle the input that carried the steering text (or write "none").
  2. Mark the step that did the harm: a tool call, or, for incident 4, the client's fetch of the rendered answer.
  3. Mark the earliest point where a control could have stopped it, and the latest. The latest is just before the harmful step happens: before the tool call executes, or, for incident 4, before the client fetches what the answer points to. For incident 4 the latest point is not a tool call, so a gateway on tool calls cannot stand there.
  4. Strike out one leg of the trifecta that, if removed, would have prevented the incident. Write down the task the agent could no longer do.
  5. Label the control at each mark: design, deterministic rule, or detector.

A worked example: incident 1, the helpful summary

Step Answer
Steering input The prospect's e-mail, read as a tool result
Harmful call send_email(to=external, attachment=contact_list)
Earliest stop When the e-mail is read: mark its text untrusted (design) or score it for injection (detector)
Latest stop At send_email: an attachment drawn from the CRM going to an external domain (deterministic rule), or a hold because the arguments carry data the untrusted e-mail could have influenced (design: taint, Module 11)
Leg to remove The way out: the agent drafts replies but a person sends them. Lost: unattended replies.

Notice that the latest point has the most information: by then you know the destination, the payload and where each argument came from. That is why the course puts the gateway at the tool call.

Then answer the check

The short answer in the module index. Keep your four drawings: Module 2 comes back to the four incidents and asks which security property each one broke, first and in the end.
