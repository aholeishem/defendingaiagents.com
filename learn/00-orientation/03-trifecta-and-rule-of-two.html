Module 00 · Lesson 03

Three capabilities make a leak: the lethal trifecta and the rule of two

Willison (2025) named the combination that makes an agent leak. An agent that has all three of:

  1. access to private data,
  2. exposure to untrusted content,
  3. a way to communicate externally,

can be made to send the first to an attacker using instructions hidden in the second, through the third. Not "might be". Can be, given enough attempts, because the only thing standing between the three is a model's judgement, and the attacker gets unlimited tries at it.

Meta's rule of two (Meta AI, 2025) turns this into a design constraint. Within a session, an agent may have at most two of:

  • A. processes untrustworthy input,
  • B. has access to sensitive systems or private data,
  • C. can change state or communicate externally.

If a task needs all three, the agent does not act alone: a person approves, or the task is split so that no single context holds all three.

C is wider than Willison's third leg. Deleting a file is not exfiltration, but it is a consequential action an injected instruction should not trigger.

Applying it

Agent A B C Verdict
Summarises public web pages for a user ✔ ✗ ✗ Fine
Answers HR questions from the internal wiki ✗ ✔ ✗ Fine
Triages the support inbox and issues refunds ✔ ✔ ✔ Needs a design change or a person
Coding agent with repo write access, reads issues from the public ✔ ✔ ✔ Same

The last two rows are the agents people actually want. That is the problem. The course spends Modules 11 to 13 on what to do about it: split the work so untrusted text never reaches the part that acts (Module 11), shrink B and C to one task's worth (Module 12), and put a person on the decisions that still need all three (Module 13).

Why "at most two" and not "detect the bad one"

Because a detector turns a structural guarantee into a probabilistic one. If 1 injection in 1,000 slips past your detector, an attacker who can send a thousand e-mails expects one through: a 63% chance of at least one if the tries are independent (1 - 0.999^{1000}), and more against an attacker who learns from each try. Removing a leg changes the probability to zero for that path, at a cost in what the agent can do. You will measure both numbers in this course: the attacks a design rules out, and the benign tasks it can no longer complete.

Check yourself

  1. A calendar assistant reads invitations from anyone and can accept them. Which legs does it hold? Is accepting an invitation "communicating externally"?
  2. An agent has only A and C. Name a harm it can still do.
  3. What is the smallest change that takes the support-inbox agent down to two legs? What task does it lose?
Answers
  1. All three: A (invitations from anyone), B (the user's calendar is private data) and C (accepting changes state). Accepting also sends a reply to the organiser, so it is external communication, and the reply can carry text; even if it carried nothing, the rule of two's C covers state changes.
  2. An integrity harm: an injected instruction makes it delete records, send spam in the user's name, or trigger a payment. No private data is needed for any of them.
  3. Take away C's refund tool: the agent triages and proposes refunds, and a person, or a separate context that never reads the tickets, issues them. A and B cannot go, because tickets are untrusted and refunds need customer data. It loses unattended refunds, the part of the job that saved the most time.
